# Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a single append-only, tenant-scoped Audit Log that records successful business changes, migrates salary history from SalaryAudit, and exposes a read-only Audit Logs module.

**Architecture:** A backend `AuditService` constructs allowlisted events from validated service-layer commands. Its repository appends the event in the same transaction as each business mutation. A scoped read service applies the caller's permission-matrix `All` or `Companies` data scope and serves cursor-paginated results to a read-only frontend module.

**Tech Stack:** Go `encoding/json`, Gin, GORM, PostgreSQL JSONB, React 19, TypeScript, Vite, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-08-audit-log-design.md`

## Global Constraints

- Audit events record successful state changes only; denied, failed, and quota-conflict commands stay in safe technical logs.
- Never serialize passwords, tokens, cookies, raw request bodies, or unallowlisted sensitive fields.
- Audit writes and their business mutation must commit or roll back together.
- The audit API has no create, edit, or delete route.
- All audit read queries apply the permission-matrix `All` or `Companies` scope server-side; code must not branch on role names.
- Use Bangkok timestamps and date-range keys according to each repository's existing date helpers.
